# 02 · 界面布局框架

> 本文档面向不懂代码的项目主人，讲清楚这套前端"长什么样、由什么拼成、为什么改一处能全局生效"。
> 所有结论都来自对 `scaffold-vue/src` 下源代码的逐文件通读，引用的路径均以磁盘真实文件为准。
>
> 先解释三个反复出现的词：
> - **Vue 组件**——可以理解为一块可反复使用的积木，每块积木是一个 `.vue` 文件，页面上看到的每个按钮、弹窗、表格都是某块积木的实例。
> - **插槽（slot）**——积木上预留的"空槽"，页面把自己的内容塞进槽里，积木负责摆好位置。写法是 `<template #槽名>`。
> - **组合式函数（composable）**——一段可以跨页面复用的"逻辑程序"，放在 `composables/` 目录，组件管外观、它管脑子和记性。

## 一、登录之后看到的整体外壳

登录页之后，所有页面都住在一个固定框架里。这个框架由 `scaffold-vue/src/components/layout/AppShell.vue` 负责，结构自外向内是：

```
舞台（浅灰底 + 微颗粒）
└─ 应用外框（一圈深色粗边框，像仪表盘外壳）
   ├─ 导航轨（左侧竖条菜单）        ← Sidebar.vue
   └─ 工作区
      ├─ 顶栏（面包屑 / 搜索 / 头像）← Topbar.vue
      └─ 内容区（真正的业务页面）    ← 路由出口，每个菜单页换着进来
```

四个部件与负责文件：

| 部件 | 负责文件 | 它做什么 |
| --- | --- | --- |
| 外壳总装 | `scaffold-vue/src/components/layout/AppShell.vue` | 把侧栏、顶栏、内容区拼在一起；页面切换动画；⌘K / Ctrl+K 快捷键（第 85–90 行）；手机窄屏（≤820px）时侧栏变抽屉加遮罩（第 32–33、110 行）；鼠标悬停菜单就提前加载目标页面代码、按下即提前请求首屏数据（第 59–83 行） |
| 导航轨 | `scaffold-vue/src/components/layout/Sidebar.vue` | 品牌标志、分组菜单（菜单来自后端，见下文）、版本号；选中项背后有一块会滑动的玻璃高亮块 |
| 顶栏 | `scaffold-vue/src/components/layout/Topbar.vue` | 折叠侧栏按钮、"你在哪个页面"的面包屑、搜索菜单入口（显示 ⌘K）、外观设置按钮、用户头像下拉（改密码 / 外观 / 退出） |
| 命令面板 | `scaffold-vue/src/components/layout/CommandPalette.vue` | 按 ⌘K / Ctrl+K 弹出的搜索框：搜页面、搜用户、执行动作（切深浅色、改密码、退出）；输入 `?` 还能进入"问系统"问答模式（第 93–95 行），例如问"谁能删除用户" |

内容区里的页面切换由 AppShell 的过渡钩子接管（第 119–125 行）：旧页 0.18 秒淡出、新页 0.62 秒推进进场，切换后自动回到页面顶部。

**页面是怎么被"装进"框架的？** 登录前只有 `/login` 一条固定路由；登录后由 `scaffold-vue/src/router/index.ts` 在第 46–67 行把后端返回的菜单动态注册成一条条路由，再统一挂在 AppShell 之下（第 9–20 行是静态部分，含 404 兜底页）。菜单和页面组件的对应关系登记在 `scaffold-vue/src/composables/auth.ts` 第 64–128 行的**页面登记表（PAGE_MAP）**里——每登记一条就写清：页面文件、取数接口、导出配置、是否树形。**这是新增业务页面时必须登记的唯一入口**，登记一次，侧栏路由、数据加载、导出能力全部自动接上。

另外两个全局常驻件在 `scaffold-vue/src/App.vue`（第 6–11 行）：右上角飘出的提示气泡（ToastHost）、确认弹窗（ConfirmHost），以及一层极淡的噪点薄膜（grain-layer），薄膜是为了让大面积渐变不发"塑料感"。

## 二、标准页面解剖：一个列表页是怎么拼出来的

以"用户管理"为样本（`scaffold-vue/src/views/system/Users.vue`）。这个页面从上到下你看到的每一段，**全部是公共积木，页面本身只提供"填空内容"**：

| 屏幕位置 | 用到的公共件 | 页面填了什么 |
| --- | --- | --- |
| 页头（标题 + 描述 + 右侧按钮） | `ListPage` 的页头 | 标题"用户管理"；右侧一个视图切换器和一个"新增用户"权限按钮（第 300–303 行） |
| 左栏（可选） | `DeptTree` 部门树 | 点部门即按部门过滤（第 357–359 行） |
| 查询区 | `SearchForm` + `Field` + `TextInput` + `DictSelect` | 两个查询字段：关键词、状态（第 361–368 行） |
| 表格面板 | `DataTable` + `Pagination`（由 ListPage 内置） | 8 个列的定义（第 30–39 行）；每列长相用 `#cell-列名` 插槽定制：头像+姓名用 `Avatar`+`HoverCard`，状态用 `StatusTag`，操作列用一排 `PermissionButton`（第 376–414 行） |
| 表格右上工具 | ListPage 内置 | 刷新、导出（自动出现，因为登记表里配了导出） |
| 勾选后的批量浮条 | ListPage 内置底部浮条 | 启用 / 停用 / 删除三个权限按钮（第 370–374 行） |
| 新增 / 编辑弹窗 | `FormDialog` + `Field` + `TextInput` 等 | 十来个表单字段和校验规则（第 416–444 行） |
| 重置密码弹窗 | `FormDialog` | 一个密码框（第 446–459 行） |
| 看板视图（可切换） | `BoardView` + `HoverCard` + `Tag` | 卡片长相、分列方式（第 305–355 行，详见第四节） |

**页面自己只写四样东西，其余一律不写**（这是本脚手架最重要的约定）：

1. **业务字段**——表格有哪些列、表单有哪些框；
2. **业务动作**——新增、编辑、删除、重置密码这些函数，以及每个动作要什么权限码；
3. **取数登记**——在 `composables/auth.ts` 的页面登记表里登记一次接口（`Users.vue` 第 25–28 行连取数函数都不用写，自动从登记表取）；
4. **插槽内容**——把上面这些填进 ListPage 预留的槽里。

查询、重置、分页、导出、勾选、加载中状态、删除最后一页后自动回退上一页、请求防错乱（只认最新一次请求的结果）……这些通用能力全部由 `useListPage`（`scaffold-vue/src/composables/list.ts` 第 119–221 行）和 `ListPage` 组件包办，任何页面都不重复实现。"字典管理"页（`scaffold-vue/src/views/system/Dict.vue`）是第二个样本：同样的 ListPage 骨架，差异只是把看板换成了"字典样本册"，并多了一个右侧抽屉（`Drawer`，第 257–281 行）展示字典明细。

## 四、同一份数据的多种视图：列表 ↔ 看板 ↔ 样本册怎么切换

这套机制由三部分咬合：

1. **开关**：`ListPage.vue` 有个 `altView` 属性（第 27–28 行）。它是"如果……则……否则……"的判断——**若 `altView` 为真，则整个查询区 + 表格区被替换成 `#alt` 插槽里的内容；否则走常规列表**（模板第 54–55 行）。`#alt` 里放什么它不管：可以是看板（用户页）、样本册（字典页）。
2. **记性**：`scaffold-vue/src/composables/view.ts` 的 `useViewMode`（第 5–20 行）负责记住用户上次选的视图——**存在浏览器本机的 localStorage 里**（键名 `scaffold.view.<页面名>`），下次进来还停留在上次的视图；如果本机存储不可用（如隐私模式）就退回默认值；窄屏首次进入还可以指定一个"窄屏默认视图"。
3. **各管各的数据**：切到另一视图时才加载该视图的数据。例如用户页第 66 行"若切到看板视图，则加载看板数据"，列表和看板互不干扰。

以两个样本页为例：`Users.vue` 第 42 行用 `useViewMode('users','table',['table','board'])` 在"列表 / 看板"间切换，第 298 行 `:alt-view="view === 'board'"` 决定是否整页换成看板；看板内还能再选"按部门 / 按角色 / 按状态"分列，其中只有"按状态"允许拖卡片改启用停用（第 41–47、316–317 行）。`Dict.vue` 第 39 行同理在"样本册 / 表格"间切换。**结论：以后你的业务页面想要"列表 + 看板"双视图，只需要一个 `useViewMode` + 一个 `#alt` 插槽，不需要自己造切换器。**

## 五、七层样式体系与主题换肤

样式（CSS——浏览器专管"长什么样"的语言）被切成七层，在 `scaffold-vue/src/main.ts` 第 8–14 行**按固定顺序**引入，一层压一层：

| 层 | 文件 | 管什么 |
| --- | --- | --- |
| 1 令牌 | `scaffold-vue/src/styles/tokens.css` | 全站"设计变量"的唯一来源：颜色（正文黑五档、主蓝、青柠、警示红）、圆角五档、阴影、四种玻璃底色、大数字字号、侧栏宽 232px / 顶栏高 64px、表格行高与单元格边距（第 7–134 行）。文件头注释即写明"页面与组件只引用令牌，不手写取值" |
| 2 基础 | `scaffold-vue/src/styles/base.css` | 格式重置、正文排版、键盘焦点环、细滚动条、噪点薄膜、无障碍降级 |
| 3 材质 | `scaffold-vue/src/styles/materials.css` | 四种玻璃配方：导航轨 / 高亮小块 / 浮层 / 阅读面，外加凹槽与鼠标跟随光斑（第 6–43 行）。差别只在透明度、模糊度和白边强度，不换颜色 |
| 4 控件 | `scaffold-vue/src/styles/components.css` | 按钮、图标按钮、表单字段、输入框等交互控件的样子 |
| 5 仪器 | `scaffold-vue/src/styles/instruments.css` | "仪表盘语汇"：眉标、大读数、深色铭牌、环比胶囊、刻度尺、图表 / 看板 / 矩阵等版式 |
| 6 外壳 | `scaffold-vue/src/styles/layout.css` | 舞台 → 深色外框 → 导航轨 + 工作区的布局骨架（第 5–29 行），侧栏折叠态等 |
| 7 页面 | `scaffold-vue/src/styles/pages.css` | 只放单个页面独有的排布，头行注释明确"通用控件不在这里写"（第 1–3 行） |

**为什么改一处全局生效？** 因为所有组件都不写死颜色和尺寸，只写"请引用某某变量"（如 `color: var(--ink)`）。换主题时，`scaffold-vue/src/composables/appearance.ts` 把选择写到 `<html>` 根元素的 `data-theme` / `data-density` 属性上（第 40–44 行），而 tokens.css 早已备好两套变量值：第 140 行起是深色主题的一整套替换值，第 136–137 行是"舒适 / 紧凑"两档表格密度对应的行高与边距。根元素的属性一变，全站引用同一变量的地方**同时**换脸——这就是"改一处、全局生效"的全部原理。

外观设置的三个选项（浅色 / 深色 / 跟随系统，舒适 / 紧凑密度，侧栏折叠）整体持久化在本机 localStorage（键 `scaffold.appearance`，appearance.ts 第 13 行）；"跟随系统"会监听操作系统的深色模式开关实时切换（第 47 行）。`main.ts` 第 17 行在页面渲染前就应用外观，避免首屏闪一下错的颜色。

## 六、动效体系与登录背景

动效（动画）只有一个入口：`scaffold-vue/src/composables/motion.ts`，基于动画库 GSAP（一个专门做网页动画的第三方库）封装。文件头立了规矩：每条动效都要能说出它表达什么（蓄力 / 放 / 进行中 / 落定 / 停摆），说不出语态的装饰动画不做（第 6–11 行注释）。统一提供：

| 能力 | 说明 | 谁在用 |
| --- | --- | --- |
| 统一缓动与时长表 | 五种缓动、十档时长集中定义（第 13–31 行），全站动画"手感一致" | 所有动画 |
| 按压 / 悬停 / 涟漪 | 事件委托实现：新控件只要类名命中清单，自动获得同一手感（第 57–105、309–348 行） | 全局自动生效，组件零代码 |
| 页面切换 / 外壳首屏入场 | AppShell 调 `pageLeave` / `pageEnter` / `playShellEntrance` | 外壳 |
| 玻璃滑块 `slideThumb` | 同一块高亮玻璃在菜单项 / 选项间滑动 | 侧栏、分段选择器、命令面板 |
| 浮层进出场 `overlayEnter/Leave` | 弹窗从"你点击的位置"放大展开；抽屉支持从被点的行"生长"出来（第 239–297 行） | 弹窗、抽屉、下拉、悬停名片 |
| 级联浮现 / 折线描绘 / 打字机 / 布局变形 | 列表行、面板内容按阅读序浮现；折线沿路径画出；文字逐字打出；卡片展开时其他卡平滑让位（Flip） | 表格、分析栏、问答、字典样本册 |
| 弹簧与帧循环 `spring` / `createFrameLoop` | 图谱节点弹簧跟随、看板卡片飞回落定；页面隐藏或滚出屏幕自动停帧省电（第 374–440 行） | 关系图谱、看板拖拽、登录背景 |

**减少动效偏好如何处理**：两道保险。第一道在 motion.ts——第 35–42 行的"是否跳过动画"检查（尊重系统的"减少动态效果"设置，或页面在后台），每个动画函数开头都问一句，命中就直接给最终状态，不给过程；第 45–50 行还保证切到后台的动画不会停在半路。第二道在 base.css 第 97–107 行——系统开了"减少动态效果"时，把所有 CSS 动画时长压到 0.01 毫秒，作为兜底。

**登录背景**：登录页（`scaffold-vue/src/views/Login.vue`）左侧是一块深色画布：Canvas 画布（网页里的"画图板"）绘制的神经网络——能力模块节点缓慢呼吸、脉冲沿连线往返，登录成功时向中心迸发并收束成一个对勾（`scaffold-vue/src/components/NeuralNet.vue` 第 5–9 行注释）；旁边有实时时钟表盘和服务健康铭牌；登录卡还会随鼠标轻微倾斜（Login.vue 第 56 行起）。

浮层的键盘无障碍（打开后 Tab 只在浮层内循环、关闭后焦点还给触发按钮）由 `scaffold-vue/src/composables/focus.ts` 统一提供，命令面板、弹窗都在用。

## 结语：给项目主人的三句总结

1. **外壳固定、页面换芯**：侧栏 / 顶栏 / 命令面板 / 深浅色 / 动效全是现成的，你只需要在页面登记表里登记新页面，然后往 ListPage 的槽里填业务字段。
2. **"必须复用"是硬约束**：第三节的清单就是你的零件目录——下拉找 DictSelect / DeptSelect / UserSelect，弹窗找 FormDialog，按钮带权限找 PermissionButton，视图切换找 altView + useViewMode。
3. **视觉与动效不可单页私改**：颜色、字号、圆角全部来自 tokens.css 一处；动效全部走 motion.ts。想调风格，改令牌和公共件，不要在单个页面里另起炉灶。
