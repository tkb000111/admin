## 二、项目一页速览

**这是什么**：一套自研的「后台管理脚手架」（脚手架＝搭好骨架、业务往里填的工程底座），技术上是 Spring Boot（Java 后端框架）+ Vue（前端框架）。已内置认证登录、菜单与按钮权限、数据权限、组织与岗位、字典、参数、操作日志和代码生成，共 **10 个管理页面 + 1 个工作台**（另有登录页、404、无权限提示页）。

**两端的技术底子（各一句话）**：

- 后端：Java 17 + Spring Boot 3.5 + MyBatis（数据库访问框架）+ MySQL（数据库）+ Redis（高速缓存，存登录令牌和验证码）+ JWT（登录令牌，即登录成功后发的一张"通行证"，之后每次请求都要出示），按 Maven 模块分五层（公共件 / 通用能力 / 业务 / 代码生成 / 启动装配），SQL 全部以注解（注解＝贴在代码声明上的标签，框架读到标签就自动执行对应动作）写在 Mapper 接口里，没有 XML 文件。
- 前端：Vue 3 + TypeScript + Vite（构建工具）+ 全自研组件库（珍珠玻璃主题，不用 Element Plus）+ GSAP（动效库），列表页统一走 ListPage 骨架，样式分七层、改一处全局生效。

**默认启动方式**（`启动.sh` 已核实存在；完整步骤以 `README.md` 为准）：

1. 前置条件：JDK 17+、Maven、Node.js 22+、MySQL 5.7+、Redis；首次使用需先建空库 `scaffold_system`，按序导入 `scaffold-system/sql/` 下的 V1（建表）、V2（初始数据）两份 SQL；环境变量 `JWT_SECRET`（登录令牌的签名密钥）必填，可执行 `export JWT_SECRET="$(openssl rand -hex 32)"` 生成。
2. 日常开发：终端一在项目根目录执行 `./启动.sh 开发`（开发后端，端口 18085，改代码自动重启）；终端二在 `scaffold-vue` 目录执行 `VITE_API_PROXY_TARGET=http://localhost:18085 npm run dev`，浏览器打开 `http://localhost:5173`。
3. 正式流程（README）：在 `scaffold-system` 目录执行 `mvn -pl scaffold-admin -am package -DskipTests`，再 `java -jar scaffold-admin/target/scaffold-admin-0.1.0-SNAPSHOT.jar`（后端 8080）；前端仍用 `npm run dev`（5173）。另有 `./启动.sh`（不带参数）一键起「网关 18090 → 后端 18091」的整栈服务。
4. 默认账号：`admin / admin123`（仅本地开发用，接入实际环境前必须改密码）。

**包含哪些页面**（已与 `scaffold-vue/src/views/` 和 `PROJECT_MAP.md` 交叉核实）：

## 三、核心卖点（3 条）与核心短板（3 条）

**卖点**（提炼自 01、02、04）：

1. **统一权限体系一条链**：登录令牌、按钮权限、数据范围、操作日志全后端统一封装，新业务接口「贴一个注解就有」，不用重复造。
2. **组件化复用程度高**：前端列表页统一用 ListPage 骨架，查询、重置、分页、导出、权限按钮全是现成件，页面只填业务字段和业务动作。
3. **体积与流畅度控制良好**：首屏主包 284KB（gzip 压缩后 105KB，普通宽带 1 秒内下载完），页面按需加载；动效、定时器、画布动画都有「用完就收」机制，未发现内存泄漏。

**短板**（只提主题，详见 03 与 04）：

1. **验证码明文返回**：属安全演示缺陷，正式对外前需更换方案。
2. **数据权限默认放行**：业务接口不显式接数据权限注解，就是「人人可见全部数据」。
3. **权限校验无缓存**：每个请求实时查库 2-3 次核权限，并发上来后最先成为瓶颈。
